## 1. Two faces: web/desktop and mobile

The same build runs in three places:

| Where | How | Notes |
|---|---|---|
| Browser | open `app/index.html` or the GitHub Pages link | data lives in that browser's localStorage |
| Windows | portable exe or installer | same data model, data lives in the app's user-data folder |
| Android | APK | portrait-friendly layout; exports use the system "save to" picker |

The UI is never more than seven tabs on the left (on phones they become a horizontal chip strip):

```
0 Tournaments   1 Setup   2 Players   3 Matches   4 Standings   5 Export   6 Season
```

**Top bar**: the tournament summary (name · players · stages · current stage) plus four buttons — `Tournaments`, `New tournament`, `Save`, `Load file` — and the language switch (`EN` / `中文`).

> On first run in Windows, SmartScreen may warn about an unsigned app: choose "More info → Run anyway".

## 2. Five-minute quick start

1. **Create**: `New tournament` → type a name → the event opens on **Setup**.
2. **Choose a format**: in "Stages", pick Swiss / single elim / double elim / round robin / groups. Defaults are sensible (Swiss, auto pairing).
3. **Add players**: **Players** → paste a name list (one per line, or separated by commas / semicolons / tabs) → `Import list`. Seeds and starting points are optional.
4. **Generate**: **Matches** → `Generate next round` (or `Generate first round` for knockouts).
5. **Record**: each match row has score boxes and buttons — `Apply` to type a score, or `A wins` / `B wins` / `Draw` to add one game at a time. `Undo game` steps back one game.
6. **Close the round**: `Finish round`. For the last round of the stage use `Finish stage & advance`, which freezes the stage ranking and seeds the next stage.
7. **Publish**: **Standings** for ranks, **Export** for a PDF / JPG / CSV / JSON save.

Everything autosaves to local storage after each action. `Undo last step` walks back one action (30 steps are kept).

## 3. Setup in detail

### 3.1 Basics

* **Tournament name** — shown in the top bar and in every export.
* **Random seed** — every draw (Swiss pairing, tiered draw, random groups) derives from this seed, so a saved event reproduces exactly the same pairings. The seed is generated once per event.

### 3.2 Match format (defaults; per-stage override)

| Field | Meaning |
|---|---|
| Games per match | how many games a match can contain |
| Games to win | winning this many games ends the match (0 = always play every game, decide by games won) |
| Record per-game scores | lets you type the score of each game (needed for "sum of scores" and custom formulas) |
| Sets per match | a layer above games: `1` = classic, `3` = best-of-3 sets, each with its own games |
| Sets decide by | `sets` (most sets won) / `games` (total games) / `points` (total points) |
| Sets to win | how many sets win the match (0 = auto majority) |

Need one stage to differ (BO1 groups, BO5 knockout)? Tick **Custom** in that stage ('Format & scoring for this stage') — otherwise stages follow these defaults.

### 3.3 Scoring (defaults; per-stage override)

| Mode | How points are awarded |
|---|---|
| Win / draw / loss / bye (custom) | fixed points for a win, a draw, a loss, a bye |
| Per match-score tier | set points for every possible final score (e.g. 2-0, 2-1, 1-1, unfinished 1-0 …) |
| Points per game won | each game won is worth N points |
| Sum of game scores | add up the per-game scores you record |
| Custom formula | an expression over `w d l gw gl gd pa pb`, e.g. `w*3 + gd*0.5` |

Also here: **draw handling** (automatic tiebreak / allow draws / judge decides) and whether every draw counts as a loss for both sides.

### 3.4 Tiebreakers

Ties are compared top-to-bottom. Use `Up` / `Down` to reorder, `Remove` to disable, `Add tiebreaker` to insert another. Built-ins include points, forfeits, warnings, Buchholz (opponents' scores), head-to-head, game difference, games won/lost, wins, progressive score, cumulative score, score difference, "stage N points", "previous stage points", initial seed and manual order.

Sub-notes:

* **Head-to-head** only decides between players who are otherwise tied (a mini-table is used when three or more are tied).
* **Stage N points** can be added per stage; later stages may compare earlier ones.
* Removing a tiebreaker really removes it: ties that used to be split will show the same rank.

### 3.5 Bye rules (odd player count)

Only an odd pool produces a bye, and at most one per round. Choose who gets it: random first round then lowest score (each player at most one bye), always the lowest score, a random player each round, or "automatic, I'll adjust it in manual pairing". Byes count as a win in the records and are also counted separately so tables can show them.

### 3.6 Match timer

Turn on "Enable per-match time limit" to give every match card its own countdown (start / pause / reset / +5 min). At timeout, the current score settles the match: the leader wins, and level scores follow the tie setting (record a draw / higher seed wins / don't settle). Matches settled at timeout are marked **unfinished** and can be scored through the "unfinished" tier of the per-match-score scoring mode.

### 3.7 Team events

Turn on "This is a team event" and the unit becomes a **team** (players in Players become teams with members).

* **One table = one match**: a team match consists of several boards, each with one player per side.
* Modes: **n vs n** (all boards at once, most board wins), **conquest** (every player on your side must win once; winners can't play again), **KOF** (loser leaves, winner stays).
* "Players per side" limits how many play (0 = everyone). Members may exceed that number.
* Entry order is always **line up, then record**: pick both players for a board, then record that board.

## 4. Formats

### 4.1 Swiss

Pairing modes: **auto** (similar scores first, rematches avoided), **random** (redraw each round), **manual** (you pair each round yourself). Set the number of rounds; a hint shows ⌈log₂(players)⌉. Players on equal points are paired within their score group, leftover players float down, and the algorithm backtracks to avoid rematches as far as possible.

Advanced switches per stage: early clinch / early elimination (see 4.6), mid-stage cut by rank, and per-stage custom format / scoring.

### 4.2 Single elimination

`Generate first round` seeds the bracket: by seed (standard slots, strong players separated), tiered draw, fully random, or manual slot placement. Byes are assigned to the highest-ranked players. Each following round is generated from the winners. Optional **third-place match**.

### 4.3 Double elimination

Everyone starts in the winners bracket; one loss drops you to the losers bracket, two losses eliminate you. The winners champion and losers champion meet in the **grand final**.

Grand-final rules (`gfMode`):

| Mode | Meaning |
|---|---|
| Reset | losers champion must win the first match to force a reset match |
| Promotable | one match, cumulative score; once the losers champion reaches the target it rises |
| None | one match decides it |
| Handicap | one side starts with N games |

**Split start**: the top N ranked players start in winners, the rest in losers (starting in losers already counts as one loss).

**Half-bracket crossover** changes **only where winners-bracket losers land in the first losers round**: the field is split into upper and lower halves by first-round slots, and the first losers-bracket round pairs an upper-half loser against a lower-half loser (crossover). After that the bracket proceeds like ordinary double elim. The structure stays standard double elimination, so:

* the losers bracket keeps the same number of rounds and matches as ordinary double elim;
* **the losers of the winners final go straight into the losers final** — they play exactly one losers-bracket match before the grand final;
* nobody can lose three times, and no spurious losers-bracket byes appear.

> History: the v2.2 implementation split the losers bracket into two independent halves whose champions met in a "losers crossover final". That added an extra round and could knock the winners-final loser out early, which does not match real double-elim brackets; rewritten in v3.0 (see CHANGELOG).

Until you commit a round (`Commit round`) no bracket state moves — that is deliberate so you can correct scores first.

### 4.4 Round robin

Circle method, 1..N cycles (cycling swaps home/away). All rounds are generated at once; results can be filled in any order.

### 4.5 Groups

Split the field into N groups (snake by seed, random, or manual), and pick the format inside each group (round robin, Swiss, single elimination). Advance the top K per group, or the top K with ties together. Groups can be finished independently; manual pairing is done group by group.

### 4.6 Early clinch / early elimination

For Swiss, round robin and groups you can decide early:

* N **wins** → clinch a seat in the next stage (the player stops playing this stage but keeps their place in the table and Buchholz),
* N **losses** → eliminated immediately,
* or cut by **rank** after a chosen round.

Clinch bonus: players who clinch early can start the next stage with bonus points (base + extra per round early).

### 4.7 Reading a bracket

Every cell names a player or a source — grey italics mean "not decided yet" (e.g. *winner of W1 M2*). The card header is the match number; the two bottom lines are the paths: **win →** next match, **lose →** where you drop ("eliminated" = nothing left). In double elimination the grand final sits on the right, on the winners row.

### 4.8 Merged bracket

With several knockout stages, "Merged bracket" draws them top to bottom with the advancing players named between stages, plus the overall champion at the end.

### 4.0 Draw handling (all formats)

Three options: automatic tiebreak game (default), allow draws (not for knockouts), judge decides. For double elimination you can additionally make **every draw count as a loss for both sides**.

## 5. Multi-stage events

Add as many stages as you like (`+ Add stage`, `Duplicate current stage`). Each stage has its own format, draw settings, advancement rule and (optionally) its own format / scoring.

When you finish a stage, the advancing players are seeded into the next stage in rank order; players whose "start stage" is later join at that point.

**Inheritance** (per stage):

* points: inherit a percentage of everything so far (`ratio`),
* record: matches / wins / draws / losses / byes / games won / games lost are carried **at face value** (no half wins),
* scores (cumulative / difference / Buchholz / progressive): inherited when "inherit scores" is on, scaled by `ratio`.

> Do not mix the two scopes: "this stage" figures drive early clinch and the event points table, while the accumulated figures drive the standings and tiebreakers.

## 6. Players

* Import: paste a list (newline / comma / semicolon / tab separated) or import a `.txt` / `.csv` file; duplicates in the current list are skipped.
* Fields: name, seed (initial placement — snake groups and bracket slots), starting points, note.
* `Renumber seeds by current order` numbers everyone by list order.
* Withdrawing / disqualifying a player settles their unplayed matches (walkover for the opponent; both withdrawn = void) and keeps their finished results.
* Team events: each row is a team; add members under it.

## 7. Matches and score entry

* Each row shows the table number, both players with their live record (W-L-D · stage points · current rank) and the match score.
* Entry options: type the score and press `Apply` (Enter in a score box does the same), or click `A wins` / `B wins` / `Draw` one game at a time, or `Undo game`.
* Round chips at the top let you jump back to any earlier round; finished matches stay editable (re-enter the score to correct it).
* Warning / forfeit counters sit under the same card and feed the tiebreakers.
* With sets: the label switches to "Set n" and, if the score is level after the last set, an extra **reset set** is offered automatically.

## 8. Manual pairing and redraws

### 8.1 Round-by-round pairing

Set the pairing mode to **manual** for Swiss / round robin / groups, then use `Arrange manually` to pick pairs; unfilled players are flagged. Groups are arranged one group at a time.

### 8.2 First-round seeding modes

By seed, tiered draw (seeds grouped into tiers, random inside), fully random, or manual placement. The draw runs when you generate the first round; `Redraw` re-runs it before play starts. Byes stay with the players entitled to them by ranking.

### 8.3 Placing first-round slots by hand

For single / double elimination you can seat players yourself in the slot table (select two slots to swap them). Withdraw later and `Redraw` if you want a fresh draw.

## 9. Standings

* Standard table: rank, player, points, matches, W / D / L, forfeits, warnings, games W-L, game difference, cumulative score, score difference, progressive, Buchholz, status, manual order.
* Knocked-out stages show a rank table derived from the bracket instead.
* Clinched / eliminated players are tagged; ranks are tie-aware (equal tiebreakers, equal rank).
* `Up` / `Down` use manual order as a tiebreaker; `Export standings JPG` / `Save PDF` publish the table.

## 10. Exports

Everything is generated in-app — **no printer is involved**.

| What | Output |
|---|---|
| Matches | PDF (auto-paginated A4) / JPG (one long image) / CSV |
| Standings | PDF / JPG / CSV |
| Knockout stage | bracket image / PDF + a rank summary |
| Full report | all stages: brackets for knockouts, tables otherwise |
| Save | JSON, to back up or move to another device |
| Player list | plain text |

CSV files open directly in Excel / WPS (UTF-8 with BOM). In the browser the file downloads to the default folder; on Windows a save dialog appears; on Android the system "save to" picker is used.

## 11. Data and backups

* All data lives in local storage on this device (browser localStorage, the Electron user-data folder, or the app's private storage on Android). **Nothing is uploaded.**
* Multiple tournaments and multiple seasons are supported; the Tournaments tab lists them.
* **Export a JSON save before the event and every few rounds.** To restore, use `Load file`. Importing a save with the same id asks whether to overwrite or keep a copy.
* Storage is around 5 MB. If saving fails you get a red warning — export a save, delete events you no longer need, then save again.
* Old saves are migrated automatically when the version adds fields.

## 12. FAQ

**Nothing happens when I double-click the exe.** Unzip everything (the `resources` folder and DLLs must sit next to the exe). If antivirus blocks it, whitelist the folder.

**The round says "unfinished" but everyone played.** Usually one table has no result, or a player is used twice. Check for empty tables (remove them in the arrange panel).

**It rejects 2:2.** Best of 3 cannot end 2:2: a side cannot exceed "games to win", and the total cannot exceed "games per match". To allow draws, switch draw handling to "allow draws".

**Someone withdraws mid-event.** Mark them withdrawn in Players. Unplayed matches are settled as walkovers, they stop being paired, and their finished results stay in the table.

**A multi-set match is stuck at 1:1.** That is a reset situation: the card offers a "reset set" — record it and the match settles.

**Where is the language switch?** Top bar, right side (`EN` / `中文`).

## 13. Points tables and seasons

Three layers:

1. **Event points table** (per event): how this event converts results into points — by rank, by wins, or by advancing. The Standings tab shows it; exports include it.
2. **Units**: either once for the whole event (final ranking) or once per stage (each stage's ranking). Stacking is configurable: stacked, or restart from zero for the players who advanced.
3. **Seasons**: several events chained into one race. Three plans:
   * **Each stop's own rules** (default and recommended): every event uses its own points table; the season only adds them up.
   * **One shared season rule**: a single rank/wins table for every stop.
   * **One full rule per stage**: each stage of each stop can have its own scoring.

Season tables show per-stop detail (`pts · rank`), the current leader, and warnings when a stop has no usable ranking. Each stop row has a shortcut to that event's points table.

Rank points are configured as tiers: each tier covers a rank range with the same points, then a per-rank step and a floor; a tier can also be marked as "advancing" for display only.
