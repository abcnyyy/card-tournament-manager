## 一、现状诊断（有具体数值，不空谈）

| 维度 | 现在 | 问题 |
|---|---|---|
| 基础字号 | `--fs-base: 16px` | 表单 label 15px、选手名 17px、表格 15px、标题 22px，正文按"阅读文章"而非"操作面板"设定 |
| 字重 | 全站 700 / 800 | 没有粗细对比，眼睛无法靠字重定位重点 |
| 边框 | 卡片 2px、表格 1px 纯黑、按钮 2px | 每个元素同等权重，页面像线框图 |
| 阴影 | `.bcard{box-shadow:3px 3px 0 #000}` | 硬阴影，只增噪不增层次 |
| 颜色 | 纯黑白（18 个变量全是 #000/#fff） | 状态（进行中/已结束/淘汰/未录入）只能靠文字表达 |
| 留白 | padding 10–14px 混用，无栅格 | 疏密随机，长页面找不到分组边界 |
| 信息密度 | 对阵页一屏 **2.5 桌**，排名页一屏 **12 行** | 25 人赛事要反复滚动 |
| 导航 | 顶部 6 个等宽 tab + 底部黑条 | 加「赛季」会变 7 个，顶部放不下；且 tab 与页面内阶段条抢层级 |

**结论**：不是"配色不好看"，是**没有层级系统**——所有元素都在喊话，于是全部听不见。

## 二、设计方向

### 2.1 目标（可验证）

1. **信息密度 +60%**：对阵页一屏 ≥6 桌，排名页一屏 ≥20 行（1440×900）。
2. **字号整体下移 1 档**：正文 16 → 14，表格 15 → 13，选手名 17 → 14，标题 22 → 19。
3. **三级视觉层次**固定：页面（背景灰）→ 卡片（白 + 1px 细边）→ 区块标题（13.5/600）。
4. **状态可扫读**：进行中 / 已结束 / 淘汰 / 待录入 用 4 种低饱和色标区分，不靠读文字。
5. **打印不退化**：`@media print` 强制转纯黑白细线，A4 一张放得下 16 人单败树。
6. **零外部依赖**不变：不引字体、不引图标库（图标用内联 SVG path）。

### 2.2 参考的对标做法

| 产品 | 借鉴点 |
|---|---|
| **Challonge** | 对阵卡片只保留「两人 + 比分 + 状态」，晋级路径用极小号灰字挂在卡下方；树状图列间距靠对齐而非分割线 |
| **start.gg** | 页面头 56px 固定 + 面包屑；比赛卡三行结构（桌号/选手/操作），状态用左侧 2px 色条；正文 13–14px |
| **Toornament** | 排名表首列与表头 sticky，横向滚动不丢上下文；数字列右对齐 + 等宽 |
| 通用后台式设计（Linear / Vercel 一脉） | 白卡 + `#E4E7EC` 1px 边 + 6–12px 圆角 + 极轻阴影；主色只用于"可点的主操作" |

### 2.3 视觉语言（替代纯黑白）

保留黑白**骨架**（这也是打印友好的基础），但引入 **1 个主色 + 3 个语义色**，都控制在低饱和：

```
主色  #2F5BEA   仅用于：主按钮、当前选中、比分领先方左侧色条
成功  #067647   已结束 / 已晋级
警示  #B54708   未完成 / 需处理
危险  #B42318   限时已到 / 淘汰
```

> 如果你更希望保持"绝对无彩色"，可以走**备选方案 B：全灰阶**——用 5 级灰（#101828→#8A94A6）+ 反白来区分，视觉更冷但打印一致性最好。视觉稿里改 6 个 CSS 变量即可切换。

## 四、"不改变功能"的边界

**改动性质**：只改 **DOM 结构与样式**，不改任何业务逻辑、数据格式、存储键、导出格式。

必须原样保留的东西（smoke 测试就靠它们）：

1. 全部 `data-act="..."` 名称、`id`（`btnSave`/`btnLoad`/`fileInput`…）、视图容器 `#view-*`。
2. `window.TMS` 的导出面（`model / store / engine / formats / consts / exporter / util`）一个不删。
3. 所有入口按钮与操作路径（生成下一轮、完成本轮、回退、打印、导出、计时、撤销…）**一个不少**。

唯一"形态变化"（需你点头）：

- **对阵卡的录入区**：`直接填比分 + 结算` 永远可见；把低频的「比分 A/B、胜者、平局、撤销上局」收进一个 `更多 ▾`。卡片高度从 ~230px 降到 ~120px，一屏桌数从 2.5 → 6。
- 若你更希望**原样平铺**，我保留平铺但缩小字号与间距，一屏约 4 桌（仍然改善，只是没那么极致）。

## 六、赛季功能设计

### 6.1 三层结构（先对齐语义）

```
赛季 Season（可多个）
 └─ 站点 Stop = 一场赛事 Tournament（可挂多个）
      └─ 阶段 Stage（赛事内已有的概念：瑞士轮 / 单败 / 双败 …）
```

「不同阶段设不同积分方式」在这一模型下有两层含义，两种都支持：

- **`unit = tournament`（默认）**：每站赛事算**一次**分，取该站最终名次（或整站总胜场）。
- **`unit = stage`**：每站赛事内的**每个阶段**各算一次分，可分别设方式、分别设是否叠加。

### 6.2 数据模型

```js
// 赛事上新增一个字段（旧存档自动补 null）
t.seasonId = 's_xxx' | null;

// 赛季（独立存储，键名 tms_season_<id>，索引 tms_season_index）
season = {
  id, name, note, createdAt,
  rule: {
    unit: 'tournament',       // tournament | stage
    stack: true,              // 默认是否与之前的计分单元累加
    mode: 'rank',             // rank | win
    // 按排名计分
    rank: { top: {1:100, 2:80, 3:65, 4:55}, step: 5, floor: 10 },
    // 按胜场计分
    win:  { perWin: 10, perDraw: 5, perLoss: 0, base: 0 },
    resetScope: 'participants', // 不叠加时：participants 只重置参与者 / all 全榜重置
    includeRunning: false,      // 是否把"进行中"的站点也先算进去（默认否）
    // 单元级覆盖，key = 't:<tid>' 或 't:<tid>#<stageIdx>'
    overrides: {
      't_ab12':        { mode: 'win', win: { perWin: 8, base: 20 }, stack: true },
      't_ab12#2':      { mode: 'rank', stack: false }
    }
  }
}
```

**计分口径**：

- `rank`：名次 → 分。只让用户填前 4 名 + 「之后每降 1 名减 X，最低 Y」，避免填 32 行表。
  并列名次默认**同分**（和现在"同分同名次"的判定一致）。
- `win`：`base + 胜 × perWin + 平 × perDraw + 负 × perLoss`。
  胜场按该单元内的比赛累计（`unit=stage` 只算本阶段，`unit=tournament` 算整站）。

### 6.3 「叠加」到底是什么（这是最需要确认的一点）

用一个 4 人 3 站的具体例子说明（名次分 100 / 80 / 65 / 55）：

| 选手 | 第 1 站 | 第 2 站 | 第 3 站 | **叠加**（全累加） | **第 3 站不叠加** |
|---|---|---|---|---|---|
| A | 1st (100) | 4th (55) | 2nd (80) | **235** | **80** |
| B | 2nd (80) | 1st (100) | 3rd (65) | **245** | **65** |
| C | 3rd (65) | 2nd (80) | 1st (100) | **245** | **100** |
| D | 4th (55) | 3rd (65) | 4th (55) | **175** | **55** |

- **叠加**：每个有比赛记录的单位都留分，总分 = 各单元之和。
- **不叠加**：该单元**重新起算**——进入了该单元的选手，之前的分数不保留，只按本单元得分排名（上表右列，名次完全翻转）。

两个待你确认的边界（我给了默认值）：

1. **没进入该单元的选手怎么办**（例如只让前 8 名打的决赛阶段）：
   - 默认 `participants`：只重置进入者，未进入者保留原分（严格照你的原话）。
   - 可选 `all`：全榜重置，未进入者本单元 0 分（排名更符合直觉，但会把淘汰选手压到底）。
2. **进行中的站点是否计分**：默认**不计**（名次未定就发分会有歧义），页面上标"待定"，结束后自动进榜。

### 6.4 引擎接口（纯函数，可单测）

```js
E.seasonUnits(season, tournaments)   // 列出所有计分单元 + 状态 + 是否计入
E.seasonTable(season, tournaments)   // { rows:[{key,name,total,stops,best,units:[...]}], units, warnings }
E.seasonRankPoints(rule, rank, total) // 名次 → 分（含并列、超表、floor）
E.seasonWinPoints(rule, w, d, l)      // 胜平负 → 分
```

- 复用现有 `E.standings()` / `E.computeElimRanking()` 拿名次与胜场，不重写判定。
- 跨赛事选手匹配：姓名归一化（去首尾空格、全角空格转半角、英文转小写）。**重名**时在赛季页提供「这是同一人 / 拆成两人」，避免把两个同名选手合并。
- 排序：总分降 → 最好名次升 → 参赛站数降 → 姓名。

### 6.5 界面

新增侧栏「统计 → 赛季积分」（与赛事列表平级），两屏：

**赛季列表**：卡片（名称 / 站数 / 选手数 / 时间跨度 / 当前领跑者）+ 新建 / 重命名 / 删除。

**赛季详情**（见 `docs/_m_season.png`）：

- 顶部 4 个 KPI：已结束站点、参赛选手、当前计分方式、是否叠加。
- 主列：积分榜（名次 / 选手 / 总分 / 站数 / 每站一列 / 最好名次），点选手展开逐单元明细。
- 副列：计分规则摘要（点「编辑」进规则页）、站点列表（状态 + 本站方式）、口径说明。
- 规则页：默认方式（按排名 / 按胜场）→ 参数 → 单元列表（每个站点 / 每个阶段一行，可"覆盖默认"并单独设叠加开关）。

**赛事列表**：每张赛事卡右上加赛季 chip，菜单里「加入赛季 / 移出赛季」。

**导出**：赛季积分榜 CSV + 可打印 HTML（沿用现有 `exporter` 的样式体系，打印转黑白）。

### 6.6 边界与异常

| 情况 | 处理 |
|---|---|
| 赛季里 0 个赛事 | 空态引导「添加赛事」 |
| 赛事未结束 | 该站灰显「进行中 · 暂不计分」 |
| 选手改名 | 按姓名匹配，改名即视为新选手（赛季页可手动合并） |
| 同一选手在两站用不同 ID | 由姓名归一化自动合并 |
| 中途退赛 | 按该站实际名次计分；无成绩则本单元 0 分并标注 |
| 删除赛事 | 自动从赛季消失（关联靠 `t.seasonId`，无悬空引用） |
| 旧存档 | `normalize` 补 `seasonId: null`，不影响任何现有逻辑 |
